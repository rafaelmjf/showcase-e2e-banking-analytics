# Foundation checkpoint — hard-gated official sample workflow

Updated: 2026-08-11

## Objective

Provide one manual workflow that can execute the complete bounded official path when
BCB access recovers, while proving now that source failures retain evidence and
cannot leak into PostgreSQL, dbt or Dagster.

## Delivered

`.github/workflows/official-sample.yml` accepts a bounded COSIF period range and
macro date range. It runs on PostgreSQL 18 and performs:

1. locked installation, lint and the full test suite;
2. live COSIF catalog discovery;
3. COSIF download/checksum/ZIP validation and profiling;
4. the independent five-series SGS profile;
5. one explicit acquisition gate;
6. official dlt loading, dbt build and `official_end_to_end` only after all four
   acquisition outcomes succeed;
7. evidence upload on both success and failure.

COSIF and macro steps use `continue-on-error` only to preserve both source outcomes.
The explicit gate checks their underlying `outcome`, not the visually normalized
step conclusion. A skipped profile is also a failed gate. All mutation and modelling
steps use the normal success condition and are therefore skipped after a failed
gate.

## Verification

[GitHub Actions run 31448296850](https://github.com/rafaelmjf/showcase-e2e-banking-analytics/actions/runs/31448296850)
was manually dispatched for COSIF 202603 and macro January 2025. It demonstrated the
intended failure path:

```text
Python tests: 47 passed
catalog: 454 records, 453 active periods, 0 parse errors
COSIF: 0/1 complete, HTTP 502
macro: 0/5 complete, HTTP 502
acquisition gate: failed
official PostgreSQL load: skipped
official dbt build: skipped
official Dagster validation/materialization: skipped
evidence upload: succeeded
```

Artifact `official-sample-202603-202603` (GitHub artifact ID `9085384703`)
contains the source catalog, failed download manifest, zero-row observation file,
five error profiles and the dbt manifest generated by the validation test. It does
not contain a dbt `run_results.json`, which is consistent with the official build
being skipped.

The compact committed record is `artifacts/official_sample_gate_summary.csv`.

## Boundary

The workflow is ready but its success path is necessarily unverified on live data.
The red run is expected source-gate evidence, not a completed WP2/WP3 load. A future
green run must still be reviewed for official row counts and accounting suitability
before it can certify checkpoints 0B–0E or unlock reporting marts.
